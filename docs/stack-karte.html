Wer am Projekt arbeitet und womit

Quickpick-Filter

Acht Regeln, die aus den Spielen einer Analyse Tipps für Kombis aussuchen. Sie rechnen keine eigene Wahrscheinlichkeit, sondern lesen, was die Analyse schon gerechnet hat, und prüfen Bedingung für Bedingung. Bedingungen, Stufen und Messwerte unten kommen direkt aus dem Code.

1 · AnalysePunkte und Chancen

Favoritenpunkte (src/favorite-criteria.ts), Remis-Punkte und Wahrscheinlichkeiten (src/model.ts) landen je Spiel im Snapshot.

2 · SnapshotSpiele mit Quoten

output/dashboard-latest.json: Tabelle, Form, direkte Duelle, Märkte mit Quoten (seit 09.11.2026 Betano, davor Tipico).

3 · RegelevaluateFixture

In src/quickpick.ts. Die erste nicht erfüllte Bedingung ist der Grund fürs Rausfallen, sonst kommt ein Tipp mit Quote heraus.

4 · Genutzt vonWo sie greifen
  • aktiv tools/quickpick-report.ts: rechnet alle Stufen an alten Spielen nach
  • aktiv test/rules/quickpick.spec.ts: hält die Regeln fest
  • aktiv tools/kombi-tipps.ts: dieselbe Regel wie „Kombi-Tipps ab 1,60“, über src/kombi-tipps.ts
  • aktiv Alte App: Quickpicker-Fenster mit Tabelle und Wettschein in apps/analyzer/src/QuickpickUI.tsx, apps/analyzer/src/quickpick.ts, apps/analyzer/src/quickpickColumns.tsx, apps/analyzer/src/quickpickParams.ts, apps/analyzer/src/betCart.ts, apps/analyzer/src/BetCartUI.tsx und apps/analyzer/src/App.tsx; Tests in apps/analyzer/src/QuickpickUI.test.tsx
  • aktiv Neo: die drei Daves-Filter mit ihrer Vorgabe-Stufe unter Predictions → Quelle „Autoren“, in apps/neo/src/neoData.ts (authorTips); Tests in apps/neo/src/neoData.test.ts. Die übrigen Filter sind dort noch nicht angeschlossen

Ablauf einer Analyse

Die Reihenfolge ist deine Vorgabe vom 05.10.2026: erst zuordnen, dann Daten nachziehen, erst am Ende analysieren. Die Schritte 3 bis 8 erledigt npm run dashboard in einem Lauf.

blauer Rand = Teil von npm run dashboard

  1. Vorher

    Vorbereiten

    npm run prepare-analysis zählt Spiele ohne Ansetzung und zeigt Teams ohne Elo. Zuordnen (Aliase) nur noch beim Tipico-Weg.

    praktisch 0 Aufrufe
  2. Vorher

    Daten nachziehen

    Teams ohne Elo: Saisons nachladen, Listen in src/elo-config.ts ergänzen, npm run elo -- build.

    kleine Nachladungen
  3. Lauf

    Quoten holen

    Jedes Spiel, für das Betano bei API-Football Quoten führt und das es laut Angebotsliste von OddsPapi bei betano.de oder Tipico gibt (jedes Spiel merkt sich, wo) (ohne OddsPapi: Ligen des früheren Tipico-Angebots; Korrekturen in data/angebot-ligen.json), mit Fixture- und Liga-ID (/odds, Seiten nacheinander, 60 Minuten im Cache). Ohne Spiel bricht der Lauf ab und schreibt nichts.

    20 bis 230 OddsPapi 0 bis 6
  4. Lauf

    Elo nachziehen

    Neue Ergebnisse aus dem Cache. Einmal pro Woche zusätzlich die laufenden Saisons aller Ligen.

    Wochenrunde bis 600
  5. Lauf

    Rechnen

    Torlinien (vorher fehlende Ligastärke nachladen), Remis-Punkte, Favoriten. Die Modelle bekommen Daten und geben Wahrscheinlichkeiten zurück.

    Ligastärke bis 300
  6. Lauf

    Snapshot schreiben

    output/dashboard-latest.json und eine datierte Kopie. Prognosen gehen zusätzlich in die Datenbank.

    0 Aufrufe
  7. Lauf

    Abrechnen

    Beendete Spiele abrechnen, danach die Kurzfassung, wie gut das Modell zuletzt lag.

    bis 200
  8. Lauf

    Sichern

    Datenbank geprüft und gepackt nach data/backups/, dann zu MEGA. Rund 15 Sekunden.

    0 Aufrufe
  9. Danach

    Lücken prüfen

    npm run coverage und npm run data-check listen fehlendes Elo, fehlende Ligastärke und Datenfehler.

    0 Aufrufe
  10. Danach

    Ansehen

    npm run neo startet Neo auf Port 5174, npm run app die alte App auf Port 5173. Beide lesen den neuesten Snapshot.

    0 Aufrufe
